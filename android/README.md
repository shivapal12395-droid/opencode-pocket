# Native Android shell

`android/` is a real Kotlin app, not a browser shortcut. It packages the exact
same vanilla web client that the PWA serves, hosts it from the APK's own assets,
and proxies the OpenCode API to the daemon running in Termux. There is no second
UI implementation and no laptop in the loop.

## Architecture

```
WebView  ──loads──▶  PocketHttpServer (127.0.0.1:8099, inside the app)
                          │
                          ├── serves /index.html, /assets/*, /sw.js from APK assets
                          └── proxies /api/*, /auth/* ──▶ 127.0.0.1:4096
                                                            (OpenCode in Debian proot)
```

- **`PocketHttpServer.kt`** — a small `ServerSocket` server. Serving the web
  client from the same origin as the API means no CORS headers are needed, POST
  bodies pass through untouched, and SSE deltas stream live. The web client
  never sees a second base URL.
- **`MainActivity.kt`** — configures a locked-down WebView (no file access, no
  universal file URLs), injects a `PocketNative` JavaScript bridge for haptics,
  clipboard, share, Downloads and notifications, and maps the hardware back
  button to the app's own sheet → chat → artifact unwind.
- **`OpencodeService.kt`** — a foreground service that starts OpenCode through
  Termux's `RUN_COMMAND` intent. `start.sh` is called with `POCKET_NATIVE=1`, so
  it starts only the daemon and skips its own Node UI server. The service is
  idempotent and `START_STICKY`.
- **`BootReceiver.kt`** — brings the service back after a reboot or an app
  update.

The web client has two small hooks for the shell: `connect()` caches the
credentials through `PocketNative.saveConfig()`, and `downloadText()` prefers
`PocketNative.saveText()` so exports land in Downloads reliably. Both are no-ops
in a browser.

Debug builds call `WebView.setWebContentsDebuggingEnabled(true)`, so the real
on-device DOM can be inspected with `chrome://inspect` or with the DevTools
protocol over `adb forward tcp:19222 localabstract:webview_devtools_remote_<pid>`.
Release builds do not expose it.

## Build

```bash
cd android
./gradlew assembleDebug
# output: android/app/build/outputs/apk/debug/app-debug.apk
```

`app/src/main/assets/` is generated by the `copyWebAssets` Gradle task from the
repository root, so the APK always contains the current web client. `local.properties`
points at your SDK and is deliberately not committed.

## Install and grant Termux access

1. Install the APK on the phone (`adb install -r app-debug.apk`).
2. In Termux, open **Settings → Allow external commands** and enable it. This
   grants `com.termux.permission.RUN_COMMAND`, which is required for the
   foreground service to start `start.sh` inside Termux.
3. Disable battery optimisation for OpenCode Pocket so the service survives the
   screen being off. Android does not guarantee permanent background execution;
   the foreground notification is what makes long turns reliable.
4. Open the app. The password can be pasted once; it is then cached in the
   app's private storage and reused on the next cold start. After a server
   restart the password rotates, so reconnect with the new one if asked.

## What is native and what is not

- The chat, artifacts, preferences, forms, queue, providers and MCP surfaces
  are the web client, unchanged in behaviour.
- Haptics, clipboard, sharing, Downloads, notifications, the file picker and
  back navigation go through the native bridge.
- OpenCode itself still runs in Termux/Debian proot. The app does not bundle or
  reimplement it.
